# 本地全双工语音系统 (TTS & Voice Agent) 测试规范与评测标准

**文档版本：** V1.0  
**制定日期：** 2026-11-15  
**适用对象：** 本地语音合成引擎 (ChatTTS)、实时语音对话系统 (Realtime Voice Agent)、语音识别评测体系 (SenseVoice STT)  
**基准硬件：** AMD Ryzen 7 9800X3D (CPU) + AMD Radeon RX 9070 XT (GPU 16GB)  

---

## 1. 测试目标与评估维度

本规范参考通用 TTS 评测标准，并结合本地端到端全双工实时通话架构定制，兼顾**客观自动化量化指标**与**主观拟人听感体验**。

### 1.1 核心测试目标
1. **发音与字词准确度**：评估普通话拼音、声韵母、轻声变调（一、不、连续三声变调）以及多音字发音准确性。
2. **多语言与专业术语**：评估英文单词、中英混杂语句、常见缩写（CPU, BLE, API, JSON 等）的处理能力。
3. **数字与文本正规化 (TN)**：评估手机号、日期、时间、货币金额、负数温度、IP地址、端口号等规范读法。
4. **抑扬顿挫与生理气口**：评估逗号换气 (`[lbreak]`)、分号/破折号深呼吸 (`[llbreak]`) 及疑问/感叹句尾调起伏。
5. **情感表达与风格迁移**：评估预设情感模式（温暖 `warm`、欢快 `happy`、沉静 `gentle`、深情朗诵 `story`）的拟人程度。
6. **边界鲁棒性与异常输入**：评估特殊字符、Markdown 标记、括号旁白等干扰文本的抗扰度与清洗表现。
7. **全双工交互性能**：量化端到端交互延迟（首包出声延迟 TTFA、首字延迟 TTFT、实时率 RTF）与声学回声消除能力。

## 2. 评测指标与量化体系

评测采用 **客观技术指标 (50%) + 主观听感评分 MOS (50%)** 结合的综合评价体系：

### 2.1 客观自动化指标（通过 SenseVoice STT 自动评估）
- **字符识别准确率 (Accuracy %)**：$\text{Accuracy} = \max(0, 1 - \text{CER}) \times 100\%$。
- **字符错误率 (CER - Character Error Rate)**：基于编辑距离（Levenshtein Distance）量化错字、漏字、多字（幻觉发音）占比。
- **实时率 (RTF - Real-Time Factor)**：$\text{RTF} = \frac{\text{生成耗时 (秒)}}{\text{合成音频时长 (秒)}}$（要求 RTF < 0.3，实现极速流式体验）。
- **音频截断与静音比率**：检测句尾是否仓促截断，以及中间换气停顿的合理时长（150ms ~ 350ms 为优）。

### 2.2 主观拟人听感维度（MOS 10 分制）

| 评测维度 | 权重 | 评分要点 (10分制) |
| :--- | :---: | :--- |
| **中文发音准确度** | 15% | 声调准确、咬字清晰，无吞音或连字含糊现象 |
| **抑扬顿挫与自然韵律** | 15% | 语调有高低起伏，问句上扬、感叹句重音，无机器人平调 |
| **停顿与生理换气** | 10% | 意群切分合理，逗号处自然吸气，句尾从容呼吸延展 |
| **情感饱满度** | 15% | 情感充沛自然，与输入文本语境高度契合，无违和感 |
| **数字与符号规范化** | 10% | 正确区分电话号与金额，日期、时间、温度读法符合中文习惯 |
| **中英文混合切换** | 10% | 英文发音纯正，中英切换流畅无断层突兀感 |
| **长文本连贯性** | 10% | 风格始终如一，音色无跳变漂移，无音质劣化 |
| **声学饱满度与音质** | 15% | 胸腔共鸣充实，辅音清晰通透，无破音、爆音或数码单薄感 |

## 3. 标准化测试语料库 (Test Corpus)

### 3.1 日常对话基础测试 (Daily Conversational)
> **目的：** 检查基础发音、咬字清晰度、口语亲切度与基础连贯性。

- `D-01`: 你好，欢迎使用本地智能语音助手，很高兴认识你。
- `D-02`: 今天天气真不错，我们要不要一起出去走走？
- `D-03`: 请问附近有没有比较好吃的餐厅？最好是人少、环境安静的那种。
- `D-04`: 等一下，我马上就回来，你先在这里等我一会儿哈。
- `D-05`: 这件事情其实没有你想象的那么复杂，我们可以慢慢来解决。
- `D-06`: 如果你已经准备好了，那么我们现在就正式开始吧！

### 3.2 情绪表达与抑扬顿挫测试 (Emotional Prosody)
> **目的：** 验证 4 大情感模式（温暖、欢快、温柔、深情）及疑问、感叹、沉痛等情感张力。

| 编号 | 情感分类 | 标准测试文本 | 重点考核指标 |
| :--- | :--- | :--- | :--- |
| `E-01` | 开心欢快 | 太棒了！我们终于成功了！这真是一个令人激动的好消息！ | 音高基频上扬，微笑感强烈 |
| `E-02` | 兴奋惊喜 | 哇！真的假的呀？我简直不敢相信自己的眼睛！ | 语气轻快，叹词富有冲击力 |
| `E-03` | 悲伤遗憾 | 有些事情，即使过去了很久，想起来还是会觉得有些遗憾。 | 语速放缓，声调低沉下潜 |
| `E-04` | 伤感失落 | 我以为我们还有很多时间，没想到这竟然是最后一次见面。 | 弱读叹气，呼吸停顿深沉 |
| `E-05` | 严肃坚定 | 你到底有没有认真听我说话？我已经解释过很多次了。 | 逻辑重音加重，节奏紧凑 |
| `E-06` | 温柔治愈 | 没关系的，不要着急，一切都会慢慢好起来的。 | 轻柔耳语感，抚平情绪 |
| `E-07` | 睡前陪伴 | 累了就好好休息一下吧，今天你已经做得很棒了，晚安。 | 慢节奏，气口细腻轻声 |
| `E-08` | 疑问求证 | 难道你从一开始，就早已经知道最终的答案了吗？ | 句尾调值显著上扬 |
| `E-09` | 惊讶反问 | 什么？你刚才说什么？这件事情真的发生了吗？！ | 问叹复合语调，停顿鲜明 |
| `E-10` | 激昂朗诵 | 乌云在天空中翻滚，暴风雨即将来临！我们要勇敢地飞翔！ | 诗歌抑扬顿挫，气势磅礴 |

### 3.3 数字、单位与文本规范化测试 (TN / Numbers)
> **目的：** 检验模型是将数字机械逐字朗读，还是按中文口语惯例正确读出。

- `N-01` (手机号码): 我的手机号码是 13800138000。 *(正确期望: 幺三八...)*
- `N-02` (日期与时间): 今天是 2026 年 11 月 15 日，现在的时间是上午 9 点 30 分。
- `N-03` (金额与小数): 这台电脑的价格是 8,599.99 元，折扣后只需要 6,880 元。
- `N-04` (负数与温度): 当前室外温度是 -5℃，最高温度预计达到 18.5℃。
- `N-05` (数学常数): 圆周率前几位约等于 3.1415926。
- `N-06` (网络地址): 服务器的局域网 IP 地址是 192.168.1.100，开放端口为 8080。
- `N-07` (商业折扣): 本季商品一律 75 折，每满 300 减 50 元。
- `N-08` (时间跨度): 请在 10:30 前完成任务，预计耗时 2 小时 15 分钟。

### 3.4 中英文混合与技术术语测试 (Code-Switching)
> **目的：** 检验多语言发音准确性、技术缩写及语言边界过渡平滑度。

- `M-01`: Hello everyone，欢迎来到今天的 AI Voice Testing 实验室！
- `M-02`: 我正在使用 Python、JavaScript 和 TypeScript 开发全新的 Web Application。
- `M-03`: 请访问 https://www.google.com 查看官方的 API Documentation。
- `M-04`: 当前主机的 CPU 使用率达到了 95%，但是 RAM 依然有足够的剩余空间。
- `M-05`: ChatGPT 和 Qwen 是两款非常强大的人工智能大语言模型。
- `M-06`: 请使用 HTTP POST 方法向服务接口发送 JSON 格式的数据包。
- `M-07`: ESP32-S3 芯片同时支持 Wi-Fi 和 Bluetooth Low Energy，也就是我们常说的 BLE。
- `M-08`: The quick brown fox jumps over the lazy dog.

### 3.5 标点符号、气口与停顿测试 (Punctuation & Phrasing)
> **目的：** 检验逗号、分号、破折号、省略号的物理换气与停顿层次感。

- `P-01` (逗号连续停顿): 乌云，像厚厚的黑色窗帘，压在心头，仿佛随时会倾盆而下。
- `P-02` (并列分号深呼吸): 如果明天下雨，我们就待在室内；如果天气晴朗，那就按照原计划出发。
- `P-03` (省略号思考叹息): 嗯……这件事情嘛，其实让我想一想该怎么告诉你。
- `P-04` (破折号转折): 我们的目标只有一个——那就是在今天彻底攻克这项技术难题！
- `P-05` (引用与引号): 他微笑着对我说：“这是我见过的最美丽的风景。”
- `P-06` (疑问接反问): 真的吗？这也太不可思议了吧？！
- `P-07` (步骤列举节奏): 第一，检查电源；第二，启动引擎；第三，确认系统就绪。

### 3.6 绕口令与复杂声韵母辨析测试 (Articulation)
> **目的：** 检查平翘舌音、前后鼻音、相近辅音的吐字清晰度与抗吞音能力。

- `A-01` (平翘舌音): 四是四，十是十，十四是十四，四十是四十。
- `A-02` (双唇音辨析): 吃葡萄不吐葡萄皮，不吃葡萄倒吐葡萄皮。
- `A-03` (前后鼻音/流音): 黑化肥发灰，灰化肥发黑，黑化肥发灰会挥发。
- `A-04` (唇齿音辨析): 八百标兵奔北坡，炮兵并排北边跑。
- `A-05` (鼻边音辨析): 牛郎恋刘娘，刘娘念牛郎，牛郎年年恋刘娘，刘娘年年念牛郎。

### 3.7 长文本连续稳定性与音色漂移测试 (Long-Text Consistency)
> **目的：** 验证 150 字以上连续合成时，是否保持音色不跳变、语速不失控、音质无劣化。

- `L-01` (科技社论，160字):
  > “人工智能正在深远地重塑我们的生活与工作方式。从智能手机上的掌上助手，到自动驾驶汽车，再到能够理解人类思维的大语言模型，智能技术已全面渗透入现实世界的方方面面。然而技术的飞速发展不仅带来了效率的奇迹，也带来了对数据隐私与技术向善的深层思考。真正决定未来的，始终是我们运用技术的心态与智慧。”

### 3.8 边界异常输入与文本清洗测试 (Robustness & Sanitization)
> **目的：** 检验大模型产生的 Markdown 格式、括号动作、特殊符号是否被完全洗净。

- `R-01` (括号动作滤除): （深深地叹了一口气）你终于来了，我已经等了很久了。 *(严禁念出括号动作)*

- `R-04` (特殊符号过滤): 价格为 $99.99，折扣 20% off，请访问 @username_test。

## 5. 评分等级与准入基线 (Baseline Acceptance Criteria)

| 综合评分 | 等级 | 评定结论 | 准入要求 |
| :---: | :---: | :--- | :--- |
| **9.0 ~ 10.0** | **卓越 (S级)** | 完美达到真人级说话水准，抑扬顿挫优美，发音 100% 准确 | 商业化实时语音通话标准 |
| **8.0 ~ 8.9** | **良好 (A级)** | 整体自然流畅，情感生动，个别复杂词汇有轻微吞音 | 生产可用，可直接日常使用 (当前系统基准) |
| **7.0 ~ 7.9** | **合格 (B级)** | 发音无原则性错误，有停顿，但略带机械播读感 | 需进一步调优韵律参数 |
| **< 7.0** | **不合格** | 存在明显跳音、音色突变、吞字严重或幻觉乱读 | 严禁合入生产分支 |

### 系统底线硬指标（必须 100% 达标）：
1. **音色漂移率 = 0%**：同一句及连续两句之间严禁出现不同人声音色突变；
2. **标签发音事故 = 0**：严禁把 `[uv_break]`、`[laugh]` 或括号旁白读出；
3. **句尾截断率 = 0%**：必须拥有 45ms 余音平滑淡出与 280ms 呼吸留白，严禁突兀刹车。

## 6. 语音引擎对比与架构演进 (Multi-Engine Architecture)

在实际语音基准测试中，我们发现了不同架构语音引擎在发音准确率、稳定性与克隆能力上的本质差异：

### 6.1 引擎架构对比与实测数据

| 维度指标 | ChatTTS (自回归离散Token) | Edge-TTS (微软高拟真神经语音) | CosyVoice 2 (流匹配Flow Matching) |
| :--- | :--- | :--- | :--- |
| **核心架构** | 类 LLM 自回归预测音频 Token | 深度神经声学对齐模型 (FastSpeech/VITS 演进) | 文本语言模型 + Flow Matching Diffusion |
| **日常准确率 (Daily)** | 91.95% (易漏读后半句、幻觉) | **98.53%** (零漏读、零幻觉) | 96% ~ 99% (音素严格约束) |
| **标点停顿 (Punctuation)**| 85% ~ 92% (依赖特定标记) | **100.0%** (自然生理停顿与呼吸) | 96% ~ 98% (细粒度气口控制) |
| **绕口令准确率 (Articulation)** | 75% ~ 82% (易连读/吞音) | **96.2%** (吐字极度清晰分明) | 92% ~ 95% |
| **端到端实时率 (RTF)** | 0.543 (单句 2.5s ~ 4s) | **0.226 (单句 ~1.1s，快 2.4 倍)** | 0.25 ~ 0.40 |
| **显存占用 (VRAM)** | 占用 4GB ~ 6GB | **0 MB (完全不占本地 GPU 显存)** | 占用 4GB ~ 8GB |
| **音色漂移率** | 偏高 (连续长句音色易跳变) | **0% (绝对稳定一致)** | 0% (绝对稳定一致) |
| **声音克隆能力** | 仅支持随机 Seed 抽卡 | 内置数十种高质男女音色 (不支持克隆) | **支持 3 秒零样本克隆用户本人声音** |

### 6.2 ChatTTS 准确率偏低的深层根因
1. **缺少强对齐约束**：ChatTTS 属于纯自回归模型，生成每个音频 token 依赖自注意力机制。在长句或复杂文本中，注意力容易发散，导致**漏读后半句**（如 D-01 漏掉“很高兴认识你”）或**自发幻觉**（如 D-06 插入“请留主”）。
2. **特殊控制符脆弱**：依赖 `[uv_break]`、`[lbreak]`，容易在未匹配时直接把字符读出来。

### 6.3 统一多引擎架构方案
我们在项目中构建了统一的 `tts_engine.py` 抽象层：
- **生产与日常高频首选**：`--engine edge --voice yunxi`（准确率 98.5%~100%，极速 1.1s 出声，发音自然生动，零显存占用）。
- **个性化声音克隆首选**：`--engine cosyvoice`（基于 3~5 秒音频克隆用户本人的音色）。
- **学术探索与实验对比**：`--engine chattts`（保留离散 Token 实验）。
